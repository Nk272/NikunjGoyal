Why running Life backwards is hard

The forward step is a simple cellular automaton: each cell looks at its 8 neighbours and applies the B3/S23 rule — a dead cell with exactly 3 live neighbours is born, a live cell with 2 or 3 live neighbours survives, everything else dies. Computing the next board is O(n) and deterministic.

Inverting it is a different animal. The map is not injective: many distinct boards can collapse onto the same successor, so a predecessor — if one exists — is generally not unique. And it need not exist at all.

  • Garden of Eden states are boards with no predecessor whatsoever. They can only appear as an initial condition, never as the output of a previous generation. Their existence was proved by Moore & Myhill in the 1960s; concrete examples exist on grids as small as a few dozen cells.
  • Deciding whether a finite Life board has a predecessor is NP-complete (it encodes Boolean satisfiability: each target cell becomes a constraint over its 9-cell neighbourhood, and these overlap into a hard CNF instance). There is no known shortcut around search.

This page solves the inverse by backtracking row by row. Once predecessor rows r−2, r−1, r are fixed, target row r−1 is fully determined — so partial assignments that violate any already-determined target cell are pruned immediately. The cells outside the grid are treated as permanently dead (a finite board). Failed (row, prev, prev-prev) profiles are memoised so the same dead end is never re-explored. This makes grids up to ~12×12 tractable in the browser; a generic per-cell SAT search would blow up far sooner.

If the solver reports no predecessor, you have very likely painted a Garden of Eden state (for the finite-board, dead-border convention used here).
